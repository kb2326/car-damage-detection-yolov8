# M7: Trust (trimmed) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove ClaimLens's controls hold when the LLM is hijacked, route near-copy photos to fraud review, and publish a system card.

**Architecture:** The red-team suite is a catalogue (`evals/redteam/attacks.toml`) whose entries point at pytest tests that run with fakes ("hijacked" mode: the fake model does what the attacker wants). A gate test keeps every attack mapped and every ASI covered; `claimlens eval-redteam` runs the listed tests and writes a report. The live mode reuses `eval-triage` on injected golden stories. The near-copy signal extends `check_integrity` with the claim memory.

**Tech Stack:** pytest, LangGraph agent with `FakeProvider`, LanceDB claim memory, `pip-audit`.

**Spec:** `docs/specs/2026-10-03-m7-trust-design.md`

## Global Constraints

- No change to decision rules or thresholds (R1 stays "any fraud signal score ≥ 0.5").
- Near-copy threshold: `NEAR_COPY_DISTANCE = 10` (ADR 0017); signal score 0.8, kind `photo_near_copy`.
- Hijacked mode needs no key and no weights (fakes); CI runs it with the normal suite.
- Live red-team spend about $1, approved by the owner on 2026-10-03.
- `uv run --no-sync` locally (MCP servers lock `claimlens.exe`).

## Review Focus

1. A photo that is both an exact copy and a near-copy must report only the exact copy (Task 1 test `test_an_exact_copy_reports_only_photo_reuse`).
2. A claim must never match its own photos (Task 1 `test_a_claims_own_photos_never_match`).
3. An attack entry pointing at a test that was renamed must fail the gate, not silently pass (Task 2 `test_every_attack_points_at_a_real_test`).
4. A hijacked agent recommending FAST_TRACK must never weaken a route the rules set for a person (Task 2 `test_a_hijacked_agent_cannot_weaken_the_route`).
5. Memory off: integrity behaves exactly as before (Task 1 `test_without_memory_nothing_changes`).

```python
NEAR_COPY_SCORE = 0.8  # a near-copy is strong evidence, a little below an exact copy (1.0)


def check_integrity(
    state: ClaimState,
    store: SQLiteEventStore,
    memory: ClaimMemory | None = None,
    photo_path: Callable[[str], Path] | None = None,
) -> tuple[FraudSignal, ...]:
    signals = _exact_copies(state, store)
    if memory is not None and photo_path is not None:
        exact = {s.detail.split()[1] for s in signals}  # "Photo p1 also appears..."
        signals += _near_copies(state, memory, photo_path, skip=exact)
    return tuple(signals)


def _near_copies(state, memory, photo_path, skip):
    others = [r for r in memory.all() if r.claim_id != str(state.claim_id)]
    found = []
    for photo in state.photos.values():
        if photo.status is PhotoStatus.REJECTED or photo.photo_id in skip:
            continue
        mine = phash_of(photo_path(photo.blob_name))
        matches = [
            (hamming(mine, theirs), record.claim_id)
            for record in others
            for theirs in record.photo_phashes
        ]
        best = min((m for m in matches if m[0] <= NEAR_COPY_DISTANCE), default=None)
        if best is not None:
            found.append(
                FraudSignal(
                    kind="photo_near_copy",
                    score=NEAR_COPY_SCORE,
                    detail=f"Photo {photo.photo_id} is a near-copy ({best[0]} bits) "
                    f"of a photo in claim {best[1]}.",
                )
            )
    return found
```

  The exact-copy loop moves unchanged into `_exact_copies` (keyed by photo id instead of parsing the detail, if cleaner). `workflow._integrity_stage` passes `deps.memory, deps.blobs.path`.
