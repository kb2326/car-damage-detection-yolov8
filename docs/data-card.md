# Data card: `damage-v1`, `parts-v1` and `fusion-eval-v1`

Following *Datasheets for Datasets* (Gebru et al., 2018). Numbers come from
`reports/data/*-stats.md`, generated by `uv run dvc repro`.

## Motivation

- **Purpose:** train and evaluate ClaimLens's damage segmentation model (`damage-v1`) and car-part
  segmentation model (`parts-v1`), whose outputs are combined to say *which damage is on which part*.
- **Built by:** the ClaimLens project (learning and portfolio project, non-commercial).

## Composition

### `damage-v1`

| Split | Images | crack | dent | glass_shatter | lamp_broken | scratch | tire_flat |
|---|---|---|---|---|---|---|---|
| train | 2,812 | 651 | 1,805 | 474 | 494 | 2,556 | 225 |
| valid | 814 | 177 | 502 | 136 | 141 | 732 | 62 |
| test | 374 | 70 | 236 | 71 | 69 | 307 | 32 |

- 4,000 images, about 1000 x 667 pixels, one or more instance masks each (polygons).
- **Class imbalance:** `scratch` and `dent` dominate; `tire_flat` is the rarest (319 instances).
- The test split is CarDD's official test split, kept frozen for comparability with the CarDD paper.

### `parts-v1`

- 3,833 images: train 3,127, valid 416, test 290; 22 part classes (bumpers, doors, lights,
  glass, mirrors, hood, trunk, tailgate, wheel).
- 147 images have no part annotations; 12 `object` instances were dropped (catch-all class).

### `fusion-eval-v1`

- 100 images sampled (seed 20261001) from the frozen `damage-v1` test split; Grounding DINO tiny +
  SAM 2.1 tiny proposed 455 part masks in 9 coarse part groups (ADR 0006).
- **133 approved, 322 rejected**; 77 images are usable (every proposal decided, at least one
  approved), 23 had every proposal rejected.
- Approved per group: wheel 40, light 35, glass 25, mirror 12, hood 11, door 10, bumpers and trunk 0.
- **Reviewer: an AI assistant (Claude), not a person.** Treat it as AI-reviewed, not
  human-verified, until a human spot-check is done. Decisions: `reviews/fusion-eval-v1.json`.
- Purpose: evaluate damage-to-part fusion in M3. It is too small and too biased toward small parts
  for training.

### Golden claims v1 (`evals/golden/v1`)

- 97 cases: 47 from v0 (3 near-duplicate photos removed) plus 50 oracle cases from the frozen
  CarDD test split. Expected routes: 30 fast-track, 62 adjuster review, 5 fraud review.
- No golden case has been human-reviewed yet.

## Preprocessing and cleaning

1. **Taxonomy mapping by name** (`config/taxonomy.toml`). Unknown labels stop the build.
2. **Data contract** (`claimlens.data.validate`). Hard errors (missing or unreadable image, size
   mismatch, unknown label, coordinates far outside the image) fail the build. Result: 0 errors.
   Warnings: 2 tiny damage instances; 147 unlabelled part images.
3. **Deduplication:** SHA-256 plus 64-bit perceptual hash, Hamming distance at most 6, clustered
   with union-find, including the golden-claims photos.
   - `damage-v1`: 5 near-duplicate groups (10 images) inside CarDD (for example ids 001882 and 003840 are
     the same photo, re-exposed); **4 images moved** so no group spans two splits.
   - `parts-v1`: **29 images moved** across splits.
   - No CarDD image is a near-duplicate of a golden-claims photo.
4. **Split rule:** a whole cluster goes to test if any member is in the source test split, else
   it is excluded if it contains a golden photo, else validation, else train. The frozen test
   split is never altered.
5. **Export:** YOLO segmentation format; degenerate polygons are dropped and coordinates slightly
   outside [0, 1] are clamped.

## Uses

- **Intended:** training and evaluating ClaimLens models for a non-commercial portfolio project.
- **Not intended:** commercial use; real claim decisions; any use that redistributes CarDD images.
- **Known limitations:** stock and web photos, not claim photos taken by drivers; strong class
  imbalance; part labels exist only for the small AI-reviewed `fusion-eval-v1` set, and mostly
  for small parts; no demographic or geographic documentation of the vehicles.

## Distribution

Images are not committed or published. The repository contains only DVC pointer files
(`data/raw/*.dvc`), the build code and the statistics. Rebuild with `uv run dvc repro` after
obtaining the sources.
